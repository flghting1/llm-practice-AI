# 邮件项目：演示与实现讲解

## 三分钟演示

1. 启动离线模式，指明页头“离线规则演示”和虚构邮件。
2. 载入样例，观察商机、售后、通知、营销和人工核实的分流。
3. 打开采购咨询，说明输入、分流依据、SOP引用及各步骤。
4. 编辑草稿，通过审核，打开留痕；解释导出只得到草稿，不会发信。
5. 打开敏感请求，说明为什么不能自动执行；展示评测报告中的两条歧义误判。

## 应能解释的实现

- 工作流在 `flow.py` 中显式连接节点，每次调用的状态互相独立。
- 模型输出经过 Pydantic 校验；调用失败进入人工处理，不悄悄切换成规则结果冒充真实模型。
- SQLite保存原始结果，审核事件同时保留原草稿、修改稿和审核人。
- 指纹基于规范化邮件内容，防止重复创建任务；版本检查防止重复审核。
- 原始课程提供思路与可参考实现，新增应用层、网页、业务规则和验收属于本次改造。

## 可以继续改进的地方

真实模型结果尚未实测；规则方法会误判业务通知。下一步应配置模型，在独立标注集上比较错误类型，而不是把开发样例的匹配率泛化到真实邮件。真实邮箱连接、授权管理、用户隔离与偏好记忆也尚未接入。
