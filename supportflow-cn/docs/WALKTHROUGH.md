# 售后项目：演示与实现讲解

## 三分钟演示

1. 指明离线规则模式、虚构订单与固定演示日期。
2. 查询1002物流，说明回复事实来自订单工具。
3. 为1001申请退款，展示 graph interrupt 和待审批状态；此时退款记录为0。
4. 人工批准后检查退款记录与对话恢复。
5. 为1003申请退款，解释超期请求即使包含“忽略规则”也不会执行。
6. 展示测试中服务重启后的退款恢复与重复退款拦截。

## 应能解释的实现

- 模型只产生工具请求，客户身份来自运行配置；订单权限、金额和期限由工具与策略层检查。
- 大额操作使用LangGraph中断，等待人工决策后恢复；拒绝审批不会产生模拟退款。
- 上游已经提供Agent、工具、人工审批和会话检查点，本次补充中文业务及持久化业务状态。
- SQLite中的退款订单唯一约束防止重复记录，单机工作台串行化图执行。
- 中文政策检索采用关键词与汉字双字片段，属于轻量检索，不是已经训练过的向量RAG系统。

## 可以继续改进的地方

真实模型、真实订单系统、用户登录、真实支付、分布式事务和多实例并发未验证。离线规则测试验证的是流程和策略约束，不能代表模型理解自由文本的能力。
